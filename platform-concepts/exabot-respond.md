# Exabot Respond

This document provides details on Exabot Respond that offers users an easy mechanism to to perform case management, running targeted campaigns (audits), viewing periodic security posture reports, and automate tasks from a centralized interface while the platform supports creating and updating of cases from within a context of a specific finding details or investigation details or monitoring details.

### Case Management

As part of security operations, it is imperative that security operations team or engineering team creates cases to take responsive action whenever security incidents occur or risks are identified or during audit reviews anomalous patterns are observed. While organizations expanding their tool chains across their portfolios coupled with multitude of attack surfaces, centralized of view for case management becomes challenging and adds to their operational expenditures and efforts.

The **Exabot Respond** detects all cases created across the platform within the context of a finding or investigation or monitoring, and presents all of them in a centralized view, effectively allowing users to perform case management with ease. The platform also allows users to create and track cases without any context (from the centralized of view) and when users find a threat or a risk or are observing an anomaly or investigating a resource, they can just attach to the case created from the centralized view. When a case is created or updated from within a context, the associated entity is automatically added to the case, making it easy for user to attach multiple related entities and track the case from a centralized interface.

### Campaigns

Security operations team, as part of compliance drives, require to periodically assess the environments for risks, by doing access reviews. Also, security engineering teams are required to perform scheduled audits to identity risks, deviations from best practices, and take mitigative actions.

The **Exabot Respond** presents a centralized mechanism to launch campaigns to group access reviews for identities/users and add each instances of a user access review to the campaign. Campaigns provide an easy and effecient way to carry out reviews and take appropriate actions as per the outcomes.

Additionally, the platform supports users to create or add to an existing campaign from within the context an identified access review case. Exaforce platform uses its machine learning models to analyse the identities and groups the identities that require access reviews, and users can select one or more identities and either create a new campaign or add to a previously created campaign. All such actions are updated to reflect from the centralized campaigns views along with suggested actions (certify or modify or investigate) along with steps to take. As part of the campaign, users can also assign the access review cases to reviewers, and reviewers can also add their suggested actions in the case. The campaigns thus offer a robust mechanism to do reviews powered by platform not only identifying the cases but also suggesting measures.

### Reports

The platform provides periodic reports on the overall security posture for all accounts of all organizations that are integrated into Exaforce. The reports contain detailed summaries for overall security posture, individual summaries for threats and risks, detailed analysis for threats and risks, trends and key findings for threats and risks detected on the identities. The platform supports periodicity of daily, weekly, and monthly report generation. Users can also setup triggers(rules) using which they will be notified immediately when a report is generated.

### Automation Rules

The **Exabot Respond** capability provides a distinguished mechanism named **Automation Rules** which users can use to create robust, wide range of automation actions that help increasing productivity to a greater extent. For example, users can easily create a rule that can send notification to user’s email address immediately when threat findings are generated by the platform and platform marks them with a recommendation for investigation. Similarly, users can create an automation rule to trigger a JIRA case when platform detects a threat finding or a risk finding. The following are some of the many scenarios automation rules support:

* Resource Creation, Updation, Deletion
* Exaforce Threat or Risk Finding
* Exaforce Case Creation or Updation
* Addition of Notes or Comments on Case
* Exaforce Security Report Generation
* Exaforce Campaign Creation or Updation
* Case Creation or Updation in Third Party Defect Tracking Tool such as JIRA

In addition to the above listed scenarios, there are more combination of scenarios supported using which users can create a number of customized automation rules to boost user productivity. The platform supports predefined rules (known as system generated rules) and user generated rules, along with controls on visibility of rules so that users can decide tenant-level visibility vs limited visibility of the rules.

💡

**Note:** The automation rules require one or more integrations to function. Integrations are connections to your environments such as Slack channels, ticketing systems, etc. Exaforce platform provides a pre-defined (shown in Console as System Generated) integration that connects your Email with which you registered to Exaforce and also defines few pre-defined automation rules that trigger email notifications using the pre-defined integration. In addition to this, you can also create integration with a custom Email server and setup automation rules to post email notifications to that server.
